---
name: add-idea
description: >-
  Park a rough idea in the backlog without defining, prioritizing, or sizing it. Use when the user
  has an idea to revisit later, or asks to note, park, jot or scribble one down.
argument-hint: "The idea"
---

Capture an idea the user has no time to define yet. When you finish, an issue labeled only
`type:idea` and `needs-clarification` exists in the Project, preserves the intent behind the
idea, and sits at the bottom of the Queue.

Capturing should cost the user almost nothing, so don't run discovery, check INVEST, investigate
the codebase, or turn the idea into a specification. Give it a short, descriptive title.

Write the body so someone who never saw the conversation understands the idea. Consider the
surrounding conversation and any context the user provided. Explain the problem, why it matters,
and what the user hoped it would enable. Connect related thoughts and make implicit context
explicit, with links where they help. Preserve a short quote from the user's original wording
when it helps retain the intent or distinguish the idea from your interpretation.

Keep the idea exploratory. Don't invent requirements, scope, solutions, or acceptance criteria,
and don't resolve questions the user left open. Record a solution the user suggested as a
suggestion, not a decision. Distinguish your own inferences from what the user said.

The issue carries no priority, effort, milestone, or assignee.
